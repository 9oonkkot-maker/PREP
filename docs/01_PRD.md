# 카페 판매·손익·재고 관리 프로그램 PRD

작성일: 2026-10-12  
상태: 추천안 적용을 완료한 PRD. 메뉴 수익성과 엑셀 기능의 구현 시점은 사용자가 개별 선택했고, 나머지 제품 범위와 운영 기준은 “앞으로 모두 추천으로 해줘”라는 위임에 따라 기획자가 추천안으로 정했다. 자료에서 확인한 사실과 구분한다.  
PRD는 프로그램이 누구에게 어떤 도움을 주고 무엇을 제공해야 하는지 정리하는 제품 요구사항 문서다.

## 1. 제품 목적

카페 운영자가 판매 기록을 입력한 뒤 메뉴별로 얼마나 남는지 확인하고, 같은 기록을 바탕으로 기간별 손익과 재료 잔량까지 파악한다. 기록을 한 번 입력해 매출 관리와 재고 확인을 연결하는 것이 1차 구현의 목적이다.

사용자가 요청한 전체 범위는 판매·비용의 직접 입력·수정·삭제, 엑셀 양식 다운로드와 기록 가져오기, 입고·폐기·실제 재고 기록, 부족 재료와 발주량 참고, 기간별 실적과 예상 손익, 저장·백업·복원이다. 이를 두 단계로 나누어 제공한다.

## 2. 자료에서 확인한 사실

검토 자료: `데이터/데이터설명.md`, `데이터/매장운영데이터.xlsx`, `데이터/매장운영데이터.json`. 설명 문서와 JSON의 항목·건수를 확인하고 엑셀의 각 시트 항목·건수 및 대표 기록을 읽었다. 두 형식의 모든 값을 대조한 전수 검증은 수행하지 않았다.

- 매장명은 프렙 카페이며 직접 구성한 가상 샘플이다. 실제 매장의 수익이나 수요를 입증하는 자료가 아니다.
- 기록 시작은 2025-07-01, 실적 마감은 2026-09-18이다. 영업 달력은 2026-09-30까지 있다.
- 금액은 원 단위, 부가세 제외다. 재료 기준단위는 g·ml·개다.
- 엑셀과 JSON은 설명 문서상 같은 기록의 두 형식이다. 같은 내용을 두 번 가져올 대상이 아니다.
- JSON의 `settings`는 비어 있다. 자료 자체에는 합의된 운영 기준이 없다. 아래 제품 기준은 대화와 추천안 위임을 통해 별도로 정한 것이다.

| 기록 | 확인 건수 | 담긴 정보와 활용 목적 |
| --- | ---: | --- |
| 공급사 | 3 | 공급사 식별번호와 이름 |
| 재료 | 11 | 재료명, 단위, 구매용량·최초가격, 납기와 여유 재고를 둘 영업일 수 |
| 메뉴 | 8 | 메뉴명, 판매기준가, 음료·디저트 구분, 레시피 버전 |
| 레시피 | 22 | 메뉴 1개에 필요한 재료와 사용량, 특정 판매채널에만 쓰는 재료 |
| 재료가격이력 | 33 | 구매가격·구매용량과 적용 시작일 |
| 영업달력 | 457 | 영업·마감 여부, 날씨, 메모 |
| 판매기록 | 6,112 | 일자·메뉴·판매채널별 수량, 당시 단가, 할인, 순매출, 수수료, 당시 개당 원가 |
| 초기재고 | 11 | 2025-07-01 영업 시작 전 재료 수량 |
| 재고기록 | 1,515 | 입고 1,302건, 폐기 189건, 실사조정 24건. 실제로 센 수량도 포함 |
| 월비용계획 | 120 | 월별 비용항목과 금액 |
| 비용기록 | 3,560 | 월비용을 날짜별로 나누어 기록한 비용, 비용항목과 배분 기준 |
| 자료정보 | 10 | 출처, 기간, 통화 등 자료 설명 |

엑셀에는 별도의 `데이터안내` 시트도 있다. 안내 내용은 판매·비용 등의 거래 기록과 구분한다.

판매채널은 매장·포장이다. 판매 한 행은 개별 주문이 아닌 하루의 메뉴·채널별 집계다. 현재 판매 자료에서 같은 일자·메뉴·채널 조합의 중복은 발견되지 않았다.

비용항목은 임차료, 인건비, 사업주 부담 보험료, 수도광열비, 관리비, 통신·소프트웨어, 광고비, 소모품·청소비다.

## 3. 기획 시 주의할 점

| 확인한 사실 | 제품 요구사항에 반영할 점 |
| --- | --- |
| 월비용계획과 비용기록은 같은 비용의 월·일 표현이다. | 별도 지출로 합산하지 않는다. 비용기록은 실제 결제일의 지출 내역으로 단정하지 않는다. |
| 마감하지 않은 달력 날짜가 있다. | 기록이 없는 미래 날짜를 매출 0인 실적으로 취급하지 않는다. 실제 실적과 예상은 구분한다. |
| 연간 자료는 일부 기간만 포함한다. | 조회 기간과 실제 기록이 있는 기간을 알 수 있어야 한다. 일부 기간 합계를 완전한 연간 실적으로 표현하지 않는다. |
| 판매 당시 가격·원가·수수료가 저장되어 있다. | 현재 가격과 과거 기록을 혼동하지 않는다. 과거 기준의 보존 정책은 9절에서 별도로 정한다. |
| 포장 전용 재료가 있다. | 포장 판매의 재료 사용과 비용을 매장 판매와 구분할 수 있어야 한다. |
| 구매가격은 한 묶음 전체의 가격이다. | 메뉴 1개의 원가와 구매 한 묶음의 가격을 혼동하지 않는다. 단위와 구매용량을 보존한다. |
| 입고는 양수, 폐기는 음수, 실사조정은 양수·음수다. | 판매에 따른 사용, 입고, 폐기, 실제 재고 확인을 구분한다. 실제로 센 수량과 조정량을 중복 반영하지 않는다. |
| 빈칸과 0은 의미가 다르다. | 미입력·해당 없음과 실제 0을 구분한다. 정보가 부족한 결과를 확정값처럼 보여주지 않는다. |
| 식별번호가 메뉴·재료·공급사를 연결한다. | 이름만 보고 서로 다른 대상을 합치지 않는다. 연결할 수 없는 기록은 확인이 필요함을 알린다. |
| 납기와 안전재고 일수는 영업일 기준이다. | 발주 참고 기능을 확장할 때 휴무일을 고려한다. 발주 계산과 상세 정책은 2차 기획에서 정한다. |

위 항목은 자료 해석의 주의사항이다. 자료에 담긴 과거 결과를 앞으로 사용할 수익성·예상 손익·발주 기준으로 그대로 확정하지 않는다.

## 4. 핵심 사용자 흐름

1. 운영자가 판매와 필요한 비용 기록을 입력한다.
2. 메뉴별 판매 실적과 수익성을 확인한다.
3. 같은 기간의 매장 손익을 확인한다.
4. 판매와 재고 기록에 연결된 재료 잔량을 확인한다.
5. 입고·폐기·실제로 센 재고를 기록하고 결과를 다시 확인한다.
6. 기록을 저장하고 백업한다. 필요할 때 백업한 내용을 복원한다.

예: 카페라떼의 매장·포장 판매를 기록한 뒤 라떼의 수익성, 해당 기간 매장 손익, 원두·우유·포장 재료 잔량을 이어서 확인한다. 메뉴 수익성에는 재료·포장·결제수수료를 포함한다. 임차료·인건비 같은 공통 비용은 매장 전체 손익에서 확인한다. 실제로 센 재고는 영업 마감 후 기준으로 기록한다.

## 5. 1차 구현할 핵심 기능

1차 구현은 핵심 흐름을 끝까지 사용해 보는 최소 기능 제품(MVP)이다. 한 매장을 운영자 한 명이 한 대의 PC에서 사용하는 웹 프로그램으로 범위를 정한다. 여러 기기 간 기록 공유와 동시 사용은 2차로 미룬다. 이는 추천안으로 정한 사용 범위이며 개발 기술이나 배포 방식의 지정은 아니다.

| 번호 | 기능 | 사용자가 얻는 결과 | 1차 범위 제한 |
| --- | --- | --- | --- |
| M1 | 제공 자료로 시작 | 메뉴·재료·레시피와 기존 판매·비용·재고 기록을 기준으로 확인 가능 | 엑셀 또는 JSON 중 한 형식을 한 번만 초기 반영. 반복 가져오기 기능과 구분 |
| M2 | 판매 기록 관리 | 일자·메뉴·채널별 판매를 직접 입력·수정·삭제 | 기존 메뉴와 매장·포장 채널 중심. 개별 주문·결제 관리 제외 |
| M3 | 비용 기록 관리 | 기간에 속하는 비용을 직접 입력·수정·삭제 | 기존 비용항목 중심. 월 계획 관리와 자동 배분 변경 제외 |
| M4 | 메뉴 수익성 확인 | 선택 기간의 메뉴별 판매 실적과 재료·포장·결제수수료를 고려한 남는 금액을 확인 | 공통 비용은 메뉴별로 배분하지 않고 매장 전체 손익에서 확인. 좋음·나쁨 같은 자동 등급 제외 |
| M5 | 기간별 실적·손익 확인 | 기록된 매출·비용과 그에 따른 손익을 함께 확인 | 일·월 조회. 실제 기록 기준이며 미래 예측 제외 |
| M6 | 재료 기록과 잔량 확인 | 입고·폐기·실제로 센 재고를 기록하고 재료별 잔량 확인 | 기존 재료 중심. 장부상 잔량과 실제 확인 기록을 구분. 미래 부족 예측과 발주량 추천 제외 |
| M7 | 저장·백업·복원 | 작업을 다시 열어 이어가고 백업으로 기록을 되찾음 | 전체 기록의 기본 저장·백업·복원만 포함. 자동 백업·변경 이력 제외 |

판매·비용 기록의 수정·삭제는 각각 영향을 받는 메뉴 실적과 매장 손익에 연결되어야 하며, 판매 변경은 재료 잔량에도 연결되어야 한다. 잘못 입력한 입고·폐기·실제 재고 기록도 수정·삭제할 수 있는 최소 범위를 포함한다. 변경 이력 보관은 2차로 미룬다.

엑셀 양식 다운로드·가져오기는 2차 구현으로 합의했다. 1차에서는 제공 자료로 시작하고 새 판매·비용 기록은 직접 입력·수정·삭제한다.

메뉴·재료·레시피·가격 이력의 자유로운 편집은 2차로 미룬다. 판매 당시 정보, 비용의 의미, 재고의 기준 시점은 9절의 추천 운영 기준을 적용한다.

## 6. 2차 구현할 확장 기능

| 우선순위 | 기능 | 확장 내용 | 2차로 미루는 이유 |
| --- | --- | --- | --- |
| 1 | 엑셀 양식 다운로드·가져오기 | 판매·비용 양식과 기록 가져오기 | 잘못된 항목·중복·기존 기록 충돌의 확인 범위가 추가됨 |
| 2 | 나머지 기간 조회 | 주·분기·반기·연간 조회 | 1차의 일·월 핵심 흐름을 먼저 검사 |
| 3 | 기준정보 관리 | 메뉴·재료·레시피·가격 이력의 추가·변경 | 앞으로의 운영 변경과 과거 실적 보존을 함께 확인해야 함 |
| 4 | 부족 재료·권장 발주량 | 부족할 가능성이 있는 재료와 구매 참고 수량 확인 | 수요, 납기, 여유 재고, 구매 묶음을 고려하는 기획이 필요 |
| 5 | 예상 손익 | 이번 달 말 예상 손익부터 제공하고 실제 실적과 구분 | 예상에 쓰는 가정과 근거를 이해할 수 있어야 함 |
| 6 | 비용 계획과 분석 확장 | 월비용계획 관리와 실적 비교, 수익성 등급 | 기본 손익을 확인한 뒤 분석 범위를 확대 |
| 7 | 기록 보호·이용 범위 확장 | 자동 백업, 변경 이력, 여러 기기·여러 사용자 이용 | 1차의 기본 저장·복원보다 운영 범위가 넓어짐 |

우선순위는 추천안으로 정했다. 공통 비용의 메뉴별 배분은 현재 채택하지 않으며 이후 별도 요구가 있을 때 검토한다. 실제 발주 전송, 회계·세무 신고, 결제기 연동, 개별 주문·환불 처리, 여러 매장 관리는 이번 범위에서 제외한다.

## 7. 4시간 구현 범위와 시간 배분 제안

기획부터 배포까지 총 240분의 목표 계획이다. 1차의 제한된 범위를 기준으로 하며, 개발·배포 환경을 준비할 수 있다는 전제가 있다. 실제 환경은 아직 조사하지 않았으므로 완료 시간은 검증된 사실이 아니다. 이 문서는 기술이나 배포 방식을 지정하지 않는다.

| 작업 | 시간 | 완료 결과 |
| --- | ---: | --- |
| 기획·핵심 기준 정리 | 30분 | 1차 범위와 결과 의미 정리 |
| 화면 설계 | 20분 | 핵심 흐름에 필요한 화면과 정보 정리  |
| 개발 | 125분 | M1~M7의 제한된 기본 기능 연결 |
| 검사 | 40분 | 입력·변경부터 손익·재고 확인, 저장·복원까지 점검 |
| 배포 | 15분 | 합의한 사용 환경에서 열고 핵심 흐름 확인 |
| 수정 여유 | 10분 | 발견한 핵심 오류 수정 |
| 합계 | 240분 | 한 매장의 기본 운영 흐름 사용 가능 |

4시간을 지키기 위해 엑셀 반복 가져오기, 미래 예측, 발주 추천, 기준정보 편집을 1차에 추가하지 않는다. 화면 꾸밈과 부가 분석을 최소화하고, 핵심 결과의 연결이나 저장·복원 검사를 생략하지 않는다. 위임받은 범위 안에서 부가 기능을 줄일 수 있지만 핵심 기능의 누락이나 4시간 목표를 충족하지 못할 사유는 명시한다.

## 8. 1차 완료 여부를 판단하는 기준

- 기존 자료를 한 번 반영하여 판매·비용·재고 기록을 확인할 수 있다.
- 판매 기록을 추가·수정·삭제하면 관련 메뉴 실적·수익성, 기간 손익, 재료 잔량이 9절의 운영 기준에 맞게 반영된다. 이후 실제로 센 재고 자체는 과거 판매 변경으로 바뀌지 않는다.
- 비용 기록을 추가·수정·삭제하면 해당 기간 손익이 바뀌고, 월비용계획과 중복되지 않는다.
- 메뉴 수익성에는 재료·포장·결제수수료가 포함되며, 임차료·인건비 같은 공통 비용은 매장 전체 손익에서 확인한다.
- 입고·폐기·실제 재고 기록을 남기고 장부상 잔량과 실제 확인 기록을 구분해 확인할 수 있다.
- 잘못 입력한 재고 기록을 수정·삭제할 수 있고, 영향을 받는 잔량을 확인할 수 있다.
- 일·월별 실적과 손익을 확인할 수 있다.
- 포장 판매가 포장 전용 재료와 연결되고, 재료 단위가 유지된다.
- 미마감 기간과 기록이 일부만 있는 기간을 완전한 실적으로 오해하지 않는다.
- 저장 후 다시 열었을 때 기록이 유지되며, 백업·복원 후 같은 기록과 결과를 확인할 수 있다.
- 자료가 부족해 판단할 수 없는 결과는 0이나 확정 결과처럼 보이지 않는다.

숫자의 정답 기준은 9절의 운영 기준에 맞춰 후속 계산 설계와 검사 단계에서 정한다. 이 문서에서는 계산식을 정하지 않는다.

## 9. 선택·위임에 따라 정한 제품 기준

## 10. 이번 문서에서 정하지 않는 항목

계산식, 화면 디자인, 개발 기술, 버튼·입력 순서·오류 처리 등 상세 동작, 코드는 정하지 않는다. 자료의 과거 계산 결과를 앞으로의 운영 정책으로 확정하지 않는다. 실제 데이터의 빈칸이나 확인되지 않은 시점은 추천안 위임을 이유로 사실처럼 채우지 않는다.
