### 발견한 문제와 수정

- 날짜 입력값이 바뀌어도 조회 조건에 반영되지 않는 문제를 브라우저 검사에서 발견했다. 날짜·월 입력의 입력 이벤트 처리를 보완하고 동일 날짜 재조회·메뉴 연결을 다시 확인했다.
- 미입력 날짜의 요약 카드가 0원으로 보일 수 있는 표시를 기록 없음으로 수정했다.
- 최종 배포 빌드에서 Zod 내부 주석에 대한 빌드 도구 경고가 있었으나 빌드 오류는 없었다. 해당 주석 제거 안내이며 최종 산출물 생성은 성공했다.
- 초기 개발 서버의 의존성 사전 처리에서 실행 환경의 접근 제한이 발생했다. 사용자 테스트는 성공한 배포용 빌드의 미리보기 서버로 제공한다. 앱 기능·계산 기준은 변경하지 않았다.

### U02 값 불일치 조사 (2026-10-12)

사용자 보고 44,699원과 안내값 31,429원이 달라 확인했다. 사용자의 입력·필터·기록을 변경하지 않고 현재 화면을 읽었다.

- 실제 조회 상태: 2026-09-18, 카페라떼, 포장, 기존 판매 13잔.
- 실제 금액: 순매출 62,400원, 개당 식재료 1,123.2원, 개당 포장 166.4원, 할인 0원, 수수료 936원.
- 계산: 62,400 − 13 × (1,123.2 + 166.4) − 936 = 44,699.2원 → 화면 반올림 44,699원. 이 기존 기록의 계산은 맞다.
- 안내했던 신규 입력 기준: 10잔, 단가 4,800원, 할인총액 3,000원, 수수료 675원, 포장 → 공헌이익 31,429원.
- 판단: 서로 다른 기록·화면을 비교한 상황이며 현재 관찰만으로 프로그램 계산 오류라고 판단하지 않는다. 신규 입력 시나리오는 통과 처리하지 않고 재확인한다. 앞선 사용자의 긍정 응답도 실제로 어느 화면에서 확인했는지는 이 관찰로 확정할 수 없다.
- 대응: 기존 기록을 자동 수정·복구하지 않음. 코드·계산 기준 변경 없음. 신규 입력창을 여는 행동부터 한 번씩 재안내한다.

## 6. 후속 요청과 EPIC 1 확인 완료

- EPIC 1은 사용자의 전체 확인으로 완료 표시한다. 앞선 세부 응답·값 불일치 조사 기록은 삭제하지 않는다.
- 남아 있던 EPIC 1 세부 확인 항목은 이번 전체 확인으로 수용되었다고 기록하며, 개별 행동을 실제 수행했다고 새로 단정하지 않는다.
- EPIC 2를 먼저 구현·검수하고 통과하면 EPIC 3으로 진행한다. EPIC 2·3의 자체 검수를 사용자 확인이라고 바꾸어 기록하지 않는다.
- 브라우저의 사용자 저장 자료는 유지한다. 사용자가 수정한 기존 판매 기록을 샘플 원본으로 재설정하지 않는다.

## 8. EPIC 3 구현·검수 결과

구현: 입고·폐기·마감 실측 등록·수정·삭제, 구매 묶음의 기준단위 환산, 전체 JSON 다운로드, 구조·연결·건수·버전 검사, 전체 교체 복원과 취소·충돌·실패 처리.

자동 검사: **3개 파일, 총 77개 모두 통과**. TypeScript 검사와 배포 빌드 통과. 복원 실패 검사는 모든 표를 포함한 작은 검사 자료에 오류를 주입해 전체 복구를 검증했다. 최초 대량 자료 실패 검사가 시간 제한을 넘겨 자료 규모를 줄였으며 검사 항목을 생략하지 않았다.

| 실제 브라우저 행동 | 관찰 결과 | 판정 |
| --- | --- | --- |
| 검사 전 전체 JSON 다운로드 | 판매 6,112·비용 3,560·재고 1,515건과 모든 기준정보 파일 확보 | 통과 |
| 우유 10묶음 입고, 구매금액 28,000원 | 10,000ml 환산, 장부 23,180→33,180ml | 통과 |
| 우유 100ml 폐기 | 장부 33,080ml | 통과 |
| 마감 실측 33,000ml 등록 | 잔량 33,000ml, 비교 차이 -80ml, 이중 차감 없음 | 통과 |
| 입고를 12,000ml로 수정 | 실측 33,000ml 유지, 비교 차이 -2,080ml | 통과 |
| 새로고침 후 오늘 기준일 조회 | 저장한 실측·잔량·수정 기록 유지 | 통과 |

자동 검사는 양수 폐기 입력의 음수 저장, 실측 0, 단위 오류·잘못된 날짜·미래 기록, 실측 중복, 다른 창 충돌, 저장 실패 시 롤백, 복원 실패 시 전체 롤백, 숫자 정밀도 보존, 빈 자료 복원 후 샘플 재주입 방지를 포함한다.

판정: EPIC 2·3 자체 검수 통과. 두 EPIC의 사용자가 직접 확인했다는 답변은 아직 없으므로 개발 계획의 완료 표시는 대기한다. 원래 사용자가 변경한 판매 기록은 검사 전 백업 내용 그대로 보존했다. 백업 파일과 화면 증거는 GitHub 업로드에서 제외한다.

남은 검사: 배포 환경의 실제 주소에서 저장·다운로드·복원 재확인, 복원 중 브라우저 종료의 실기기 검사. 빌드에는 묶음 크기 경고가 있으며 오류는 아니다. Vercel 배포는 아직 수행하지 않았다.
