# 카페 판매·손익·재고 관리 기능 요구사항 문서(FRD)

작성일: 2026-10-12  
상태: 사용자 선택 A와 “앞으로 모두 네가 추천하는대로 해 줘”라는 위임을 반영한 완료본. PRD의 1차 범위를 유지한다. 새로운 상세 기준은 기획자의 추천으로 정한 것이며 자료에 원래 있던 사실과 구분한다.

FRD는 사용자가 무엇을 입력하거나 선택하면 프로그램이 무엇을 처리하고 어떤 결과를 보여주는지 설명하는 문서다. 코드와 기술 선택은 TRD에서 다룬다.

## 1. 근거, 범위와 읽는 방법

- 근거 문서: `docs/01_PRD.md`.
- 확인한 시안: `design/_1` 손익 대시보드, `_2` 판매 관리와 입력창, `_3` 메뉴 수익성, `_4` 비용·백업·복원, `_5` 재고 관리와 입력창. 각 폴더의 `screen.png`와 `code.html`을 확인했다.
- `design/artisanal_operations/DESIGN.md`의 기간·상태·단위 표시 원칙을 참고했다. 여기에 언급된 교대·가맹점·정산 승인 등은 승인된 기능으로 간주하지 않는다.
- 현재 원자료는 `data/매장운영데이터.json`, `data/매장운영데이터.xlsx`, `data/데이터설명.md`에 있다. PRD의 `데이터/` 표기는 현재 폴더명 `data/`와 다르지만 같은 자료를 가리킨다.
- 시안은 고정된 예시 화면이며 버튼·숫자가 실제 구현·계산·검증 완료를 입증하지 않는다.
- 문서에서 **유지**는 PRD의 요구, **추천 적용**은 위임받아 정한 상세 기준, **제외**는 1차에서 작동시키지 않는 기능이다. 확인되지 않은 원자료 값은 추정해 채우지 않는다.

### 사용 범위와 제공 기능

한 매장·운영자 한 명·한 대의 PC에서 사용한다. 판매 입력 → 메뉴 수익성 → 기간 손익 → 재료 잔량 확인을 연결한다. 모든 금액은 원·부가세 제외이며 수량의 기준단위는 g·ml·개다.

| PRD | FRD 기능 | 단계 | 주요 결과 |
| --- | --- | --- | --- |
| M1 제공 자료로 시작 | F01 초기 자료 반영 | 1차 | 기준정보와 과거 기록을 한 번 반영 |
| M2 판매 관리 | F02 판매 조회, F03 판매 추가·수정·삭제 | 1차 | 판매 목록·계산 미리보기·연결 결과 갱신 |
| M3 비용 관리 | F04 비용 조회·추가·수정·삭제 | 1차 | 기간 귀속 비용과 손익 갱신 |
| M4 메뉴 수익성 | F05 메뉴별 실적·수익성 | 1차 | 판매량·순매출·원가·수수료·공헌이익 |
| M5 기간 실적·손익 | F06 일·월 실적과 손익 | 1차 | 매장 전체 매출·비용·손익·기록 상태 |
| M6 재료 관리 | F07 재료 잔량·변동 조회, F08 입고·폐기·실측 관리 | 1차 | 재료별 잔량·실측·차이와 수정 결과 |
| M7 저장·백업·복원 | F09 저장, F10 전체 백업, F11 전체 복원 | 1차 | 재열기 후 기록 유지·JSON 백업 파일·전체 기록 복구 |
| PRD 2차 기능 | E01~E07 확장 기능 | 2차 | 12절에 별도 정리. 1차 구현 요구와 구분 |

실제 자료는 가상 매장 샘플이다. 메뉴 8개, 재료 11개, 공급사 3개, 레시피 22건, 가격 이력 33건, 달력 457일, 판매 6,112건, 초기재고 11건, 재고 변동 1,515건, 비용 3,560건, 월비용계획 120건이다. 과거 기록은 2025-07-01~2026-09-18, 달력은 2026-09-30까지다. 이 날짜를 현재 날짜나 영구적인 실적 한계로 고정하지 않는다.

## 2. PRD·시안 차이와 처리 기준

범위 차이는 사용자가 A를 선택했으므로 **PRD 우선**으로 처리한다. 누락된 필수 기능의 보완은 새 기능 추가가 아니다. 시안에만 있는 기능은 승인 없이 1차에 추가하지 않는다.

| 시안에서 확인한 차이 | 1차 처리 |
| --- | --- |
| `_1` 주문 건수·건당 단가·POS 연동 | 주문 자료가 없으므로 표시하지 않는다. 판매 수량·기록 행 수를 구분한다. POS 연결 없음 |
| `_1` Excel 다운로드, `_3` 다운로드·리포트 출력, `_5` 엑셀 다운로드 | 실적 파일 내보내기는 PRD에 없는 기능이다. 1차 제외. 엑셀 입력 양식·가져오기라는 2차 기능과도 구분 |
| 공통 상단 마감 기록하기·승인 완료 | 마감 상태 조회는 유지하되 승인·정산·마감 변경 기능은 1차 제외. 버튼을 작동하는 것처럼 제공하지 않음 |
| 공통 알림·동기화·별도 달력·프로필·시스템 설정 | 승인된 별도 기능이 아니므로 1차 동작 없음. 날짜 선택에 필요한 달력 아이콘만 조회·입력에 연결 |
| `_3` 레시피·원가 수정, `_5` 안전재고 주의 | 기준정보 편집과 미래 부족 판단은 PRD의 2차 기능 |
| `_3` 효자 메뉴·원가 점검 등급, `_1` 양호·손익분기 달성·전월/전주 비교·예산집행 | 1차 자동 판단·비교 기능 제외. 데이터 완전성에 대한 확인 필요 표시는 유지 |
| `_3` 감사 기록 보기, `_4` 암호화 선택·암호화 활성화 | 변경 이력·암호화는 1차 기능으로 채택하지 않음. 보호를 이미 제공하는 듯한 문구 제거 |
| `_4` 비용 수정만 있고 삭제·입력창 없음 | 기존 8개 비용항목에서 기록 추가·수정·삭제하는 동작을 보완. ‘신규 비용 항목 입력’은 ‘새 비용 기록 입력’ 의미로 정정 |
| `_5` 재고 이력보기만 있고 수정·삭제 없음 | 이력의 기록별 수정·삭제를 보완. 입고창만 있으므로 폐기·실측 입력 상태도 정의 |
| `_2` 수수료율/금액 혼용, 2.5% 고정 예시 | 실제 수수료 **금액** 입력 하나로 통일. 미입력은 확인 필요, 실제 0은 허용 |
| `_2` 할인 목록에 -5,000원 | 할인 입력·보존은 공제할 금액의 양수로 통일. 할인 두 번 차감 금지 |
| `_5` 잔량 안내식에 폐기 누락 | 폐기와 실측 없는 조정도 잔량에 포함. 실측 있는 조정은 기준점으로 한 번만 반영 |
| `_4` 월 임차료 전액을 하루에 표시하며 ‘일할’ 표기 | 원자료의 일별 비용기록을 사용. 월 전액을 임의로 일별 비용에 더하거나 재배분하지 않음 |
| `_5` 최근 실측과 현재 장부 잔량을 곧바로 비교 | 실측 **동일 시점**의 장부량과 비교. 오래된 실측을 현재 재고인 것처럼 표시하지 않음 |
| 시안의 메뉴·재료·공급사·가격·레시피가 원자료와 다름 | 원자료 식별번호와 값을 사용. 시안 예시는 복사하지 않음 |
| 고정 합계·검증 통과·안전 허용 오차·사업자번호·연락처 | 실제 기록과 수행한 검증에 근거한 값만 표시. 근거 없는 예시 문구·개인정보 제거 |

실제 메뉴는 아메리카노, 카페라떼, 바닐라라떼, 초콜릿라떼, 말차라떼, 레몬에이드, 크루아상, 치즈케이크다. 예를 들어 자료의 라떼 기준가는 4,800원이고 원두 사용량은 20g이다. 시안의 5,000원·18g을 실제 기준으로 사용하지 않는다.

## 3. 공통 사용 규칙

### 기간과 상태 — 추천 적용

- 일 조회는 선택 날짜, 월 조회는 선택 월의 달력상 첫날~마지막 날이다. 새 기록의 날짜는 한국 날짜 기준이며 미래의 실제 거래 기록은 저장하지 않는다.
- 기존 영업달력의 영업 여부·마감 여부는 보존한다. 기간 합계에 들어가는 비용은 휴무일에 귀속된 비용도 포함한다.
- 마감된 날짜의 확인된 기록은 확정 실적으로 볼 수 있다. 마감 전 날짜에 실제로 입력한 기록은 조회·계산하되 **입력 실적(잠정)**으로 구분한다. 입력만으로 날짜 전체의 기록 완료를 선언하지 않는다.
- 월 화면은 마감된 기록의 합계와 미마감 입력분을 구분하고, 둘을 포함한 합계를 표시하면 잠정임을 명시한다. 시안의 확정 실적 부분은 마감된 날짜만 대상으로 한다.
- 새 날짜에 달력 정보가 없으면 입력은 허용하지만 ‘영업·마감 상태 미확인’이다. 날씨·영업일 수를 추측하지 않는다. 별도의 달력 관리 기능은 추가하지 않는다.
- 미마감·미입력 날짜는 그래프의 0원 막대로 채우지 않는다. 마감 완료로 확인된 날에 판매가 없으면 매출 0원일 수 있고, 비용은 그대로 남는다.
- 기간 일부만 기록되어 있으면 조회 기간·마감 확인 범위·미마감 입력 범위를 함께 보여준다. 미래 예상 금액은 1차에 표시하지 않는다.
- 메뉴·판매채널 필터는 판매·메뉴 분석에 적용한다. 매장 전체 손익의 공통 비용을 메뉴 필터에 맞춰 임의 배분하지 않는다.

### 저장과 취소 — 추천 적용

입력창에서 값을 바꾸면 미리보기만 바뀐다. **저장 버튼을 누르고 저장이 성공한 뒤** 목록과 다른 화면 결과가 바뀐다. ‘실시간 반영’은 입력 중 원본을 바꾼다는 뜻이 아니다. 취소·닫기는 저장 전 변경을 버리며, 변경한 내용이 있을 때 버릴지 확인한다.

추가·수정·삭제는 한 작업 전체가 성공하거나 아무것도 바뀌지 않아야 한다. 저장 중 중복 클릭을 막는다. 저장 실패 시 입력 내용과 기존 저장 기록을 보존하고 재시도를 안내한다. 삭제는 대상·일자·연결 결과 영향을 확인한 뒤 실행한다. 취소하면 아무 기록도 삭제하지 않는다.

## 4. F01 초기 자료 반영

| 구분 | 요구사항 |
| --- | --- |
| 시작 조건·행동 | 저장된 운영 자료가 없는 첫 시작 시 제공 JSON을 한 번 반영. 엑셀과 JSON을 동시에 합치지 않음 |
| 처리 | 날짜·금액·수량·식별번호·참조 관계·단위를 검사. 자료정보와 가격 이력·달력·월비용계획까지 보존. 기존 원가·수수료·순매출은 원본 값 유지 |
| 화면 결과 | 가상 샘플임을 표시하고 실제 반영 건수·기록 기간을 표시. 각 관리 화면에서 조회 가능 |
| 저장·파일 결과 | 초기 반영 완료 상태와 전체 자료 저장. 새 다운로드 파일 없음. 새로고침·업데이트 때 다시 넣지 않음 |
| 실패·예외 | 파일을 읽지 못함, 필수 표 누락, 중복 ID, 연결 없는 메뉴·재료, 맞지 않는 단위는 반영 중단. 기존 자료가 있으면 초기 반영 건너뜀 |
| 값 불일치 | 과거 순매출·원가 등 계산값 불일치는 자동 수정하지 않음. 원본과 문제를 보존하고 해당 결과에 확인 필요 표시. 필수 구조 오류와 값의 불완전성을 구분 |

고유 ID는 기록을 구분하는 번호다. 판매에는 같은 날짜·메뉴·채널 조합도 하나만 있어야 한다. 실제로 여러 건 있는 비용·입고는 단순히 날짜·금액이 같다고 중복 삭제하지 않는다.

## 5. F02~F03 판매 기록

### 조회와 시안 조작 연결

`영업 일자`, `메뉴 필터`, `전체/매장/포장`, `조회`는 조건에 맞는 기록을 보여준다. `초기화`는 조회 조건·선택 표시만 초기값으로 돌리고 기록을 삭제하지 않는다. 목록은 날짜·메뉴·채널·수량·당시 단가·할인·순매출·식재료 개당원가·포장 개당원가·수수료·완전성 상태를 보여준다. 시안의 ‘당시 개당원가’는 식재료와 포장 합계 및 구분값을 함께 확인할 수 있게 한다.

필터 조건의 합계는 목록의 모든 해당 행을 기준으로 하고 페이지에 보이는 행만 합산하지 않는다. 행 선택·전체 선택은 현재 표시된 페이지에만 적용하며 선택 건수를 보여준다. 페이지 이동·조건 변경 시 선택을 해제한다. 이전·다음 페이지는 기록이 없으면 비활성화한다. 결과 0건은 ‘기록 없음’이며 미입력 기간의 실적 0 확정과 구분한다.

### 입력 항목 — 추천 적용

| 항목 | 입력·처리 기준 |
| --- | --- |
| 판매 일자 | 필수. 유효한 날짜, 초기재고 기준일 이후, 미래 날짜 제외 |
| 메뉴 | 필수. 원자료의 기존 8개 메뉴 중 선택 |
| 채널 | 필수. 매장·포장 중 선택 |
| 판매 수량 | 필수. 양의 정수. 0건 기록 대신 기록 없음 또는 기존 기록 삭제 사용 |
| 판매 당시 단가 | 필수. 0 이상 원 정수. 신규는 메뉴 기준가를 제안값으로 보여주고 실제 단가로 수정 가능 |
| 할인 총액 | 0 이상 원 정수. 할인 없음은 명시적인 0. 수량 전체에 대한 할인이며 판매 총액을 초과할 수 없음 |
| 결제수수료 금액 | 실제 금액을 입력. 0 이상 원 정수. 미입력 허용하되 수익성·손익에 확인 필요. 2.5% 자동 확정 없음 |
| 당시 개당원가 | 신규는 적용 레시피와 판매일의 재료가격으로 산출해 보여줌. 초기 과거 기록의 저장 원가는 재계산해 덮지 않음 |

### 추가·수정·삭제

| 행동 | 처리 | 화면 결과 | 저장·파일 결과 |
| --- | --- | --- | --- |
| `신규 판매 기록 입력` | 입력창 열기. 값 변경 때 C01~C03으로 미리보기 | 순매출·식재료비·포장비·수수료·공헌이익·확인 필요 사유 | 저장 전 원본 변경·파일 생성 없음 |
| `기록 저장하기` | 항목 검사 → 중복 조합 검사 → ID 부여 → 저장 | 목록·메뉴 실적·기간 손익·재료 잔량 갱신 | 새 판매 한 행과 당시 원가·레시피 기준 보존 |
| 행 `수정` | 원래 값을 불러옴. ID 유지. 바뀐 내용만 반영 | 변경 전후 미리보기, 성공 후 관련 결과 갱신 | 원래 한 행 교체. 복제 행 생성 안 함 |
| 행 `삭제` / `선택 삭제` | 선택 대상 확인 후 삭제. 여러 행 삭제는 전부 성공 또는 전부 취소 | 삭제 행 제외 후 모든 연결 결과 갱신 | 대상 행 삭제. 다운로드 파일 없음 |
| `취소` / 닫기 | 저장 전 입력 버리기 확인 | 입력창 닫힘, 목록 유지 | 저장 자료 변화 없음 |

수량·단가·할인 변경 시 순매출·총 원가는 다시 계산하지만 수수료 금액은 실제 입력값이므로 임의 변경하지 않고 재확인을 안내한다. 날짜·메뉴·채널·레시피 적용 조건이 바뀌면 새 조건의 원가를 미리 보여주고 저장 때 그 기준을 사용한다. 단순 수량 수정은 당시 저장된 개당원가를 유지한다. 수정하지 않은 당시 단가·수수료는 오늘 값으로 바꾸지 않는다.

오류: 날짜·숫자 형식 오류, 음수 수량·단가·할인, 할인 초과, 존재하지 않는 메뉴는 저장을 막고 해당 칸 안내. 같은 날짜·메뉴·채널의 추가는 기존 기록 수정 안내이며 자동 합산·덮어쓰기하지 않는다. 판매일에 레시피·가격이 없으면 원가 확인 필요로 저장할 수 있지만 관련 이익·해당 재료 잔량을 확정하지 않는다. 수수료가 순매출보다 크면 오류로 잘라내지 않고 손실 가능성을 알린다.

## 6. F04 비용 기록

비용은 돈을 지급한 날이 아니라 **실적에 포함할 날짜(귀속일)**를 기준으로 관리한다. 기존 일별 배분 비용은 보존한다. 사용자는 같은 임차료의 월 계획 금액을 다시 지출로 추가하지 않도록 안내받는다.

- 입력: 귀속일, 기존 8개 비용항목, 금액은 필수. 금액은 0 이상 원 정수이며 0도 명시적으로 기록할 수 있다. 내용·메모는 선택이다.
- 새 비용 기록은 사용자가 지정한 날짜에 속한다. 기존 ‘월비용 일할 배분’ 등 원자료 설명은 표시·보존하지만 월 비용을 자동 배분하는 기능은 없다.
- `새 비용 기록 입력`과 `간편 입력 열기`는 같은 입력 기능이다. `수정`은 같은 ID로 기존 행을 바꾸고 `삭제`는 대상 확인 후 삭제한다. 시안에 없는 삭제 조작을 보완한다.
- 기간·항목 필터와 날짜 정렬은 비용 목록에만 적용한다. 해당 목록의 건수·항목별 금액·합계를 표시한다. 별도 파일 생성 없음. 성공 시 손익과 저장 상태 갱신.
- 같은 날짜·항목·금액도 별도의 실제 비용일 수 있어 자동 병합하지 않는다. 동일 내용의 기존 기록이 있으면 중복 가능성을 알리고 사용자가 확인한다.
- 미래 귀속일·초기 자료 시작 전 날짜·음수·문자 금액·미선택 항목은 저장을 막는다. 환급·환불 등 음수 비용 처리는 1차 범위 밖이다.
- 저장 실패·삭제 취소는 기존 기록 유지. 비용 메모에 고객 이름·연락처 같은 불필요한 개인정보를 넣지 않도록 입력 안내한다.

## 7. F05~F06 메뉴 수익성과 매장 손익

### F05 메뉴 수익성

일·월과 메뉴 분류(전체/음료/디저트)를 선택하면 C01~C04를 집계한다. 메뉴별 판매량은 매장·포장을 나누어 표시한다. ‘공헌이익’은 **판매금액에서 재료·포장·결제수수료를 고려해 남는 금액**이며 임차료·인건비까지 고려한 최종 매장 이익과 다르다.

목록 결과: 메뉴, 분류, 매장·포장 수량, 순매출, 식재료비, 포장비, 수수료, 공헌이익, 공헌이익률, 기록 완전성. 합계 이익률은 메뉴별 비율의 단순 평균이 아니다. 음료의 잔·디저트의 개를 주문 건수라고 표시하지 않는다.

행 클릭은 선택 메뉴의 **읽기 전용** 설명을 보여준다. 해당 기록의 레시피 버전·재료 사용량과 당시 저장 개당원가를 구분한다. 기간에 여러 가격이 있으면 판매량 기준 평균 개당원가와 적용 날짜 범위를 표시하며 하나의 ‘당시 가격’으로 단정하지 않는다. 재료별 참고 원가가 과거 저장 원가와 다르면 둘을 같다고 꾸미지 않는다. 레시피 편집 버튼은 1차 제외.

`손익 기준서 보기`는 계산 기준 설명을 보여주는 조작으로만 사용한다. 최고·최저·효자 메뉴 등 별도 자동 판단 카드, 다운로드·감사 기록·인쇄 조작은 제외한다. 조회로 저장 기록이나 파일은 바뀌지 않는다.

누락 원가·수수료·불일치 기록이 있으면 해당 메뉴 이익을 ‘확인 필요’로 표시하고 사유·문제 행 수를 보여준다. 알려진 매출 등 독립된 값은 표시할 수 있지만 일부 값의 합계를 전체 이익인 것처럼 표시하지 않는다. 순매출 0일 때 이익률은 계산 불가이며 0%로 채우지 않는다.

### F06 매장 손익

`손익 대시보드`에서 일·월을 선택하면 전체 매장의 순매출, 식재료 사용원가, 포장비, 결제수수료, 공통 운영비용, 운영손익과 이익률을 C05로 보여준다. 날짜별 목록은 동일 기준을 사용하며 `전체 내역 열기`로 선택 기간의 전체 날짜 목록을 확인한다. 시안의 ‘최근 5영업일’은 영업·마감이 확인된 최근 최대 5일만 표시하고 월 전체 합계와 구분한다.

판매채널·비용항목별 구성과 날짜별 추이는 같은 원본 집계를 사용한다. 공통 비용은 음식·포장 원가에 섞어 메뉴에 나누지 않는다. 근거 없는 주문당 단가·성장률·예산집행·손익분기 달성 판정은 표시하지 않는다. `상세 필터`는 기존 기간 조회 조건 확인만 연결하며 새로운 조건을 추가하지 않는다.

기간 기록 부족·원가 미확인·비용 누락 가능성이 있으면 잠정·확인 필요 상태를 표시한다. 확정/잠정 합계의 기간을 명시한다. 원자료의 월계획은 합산하지 않는다. 파일 생성·원본 수정 없음.

1차 운영손익은 판매에 사용한 재료와 등록된 공통 비용 기준이다. 재료 구매대금은 별도 비용으로 중복 차감하지 않는다. 폐기·실사차이는 수량에 반영하며 **별도 폐기손실 금액은 1차 손익식에 포함하지 않는다**. 원자료에 비용이 충분히 기록되어 있다는 보장도 없으므로 법정 회계상 최종 이익이나 확정 세무 결과로 표현하지 않는다. 폐기손실 금액 기능은 승인 없이 추가하지 않는다.

## 8. F07~F08 재료와 재고 기록

### 조회

재료명·식별번호 검색과 기존 공급사 필터, 조회 기준일로 재료별 잔량을 확인한다. 원자료의 11개 재료·3개 공급사를 사용한다. `전체`는 모든 해당 재료, `조정 발생`은 비교 가능한 최신 실측의 차이가 0이 아닌 재료다. 안전재고 주의 필터·잔여 일수 판정은 2차다. 원자료의 안전재고 일수는 설정값 설명으로만 표시할 수 있고 현재 버틸 수 있는 일수로 바꾸지 않는다.

결과: 기준일, 재료·단위·공급사, 기준일 장부 잔량, 최근 실측수량과 그 날짜, 그 실측 시점의 조정 차이, 최근 입고일. 실측 기록이 없으면 ‘실측 없음’이다. 서로 다른 g·ml·개를 한 총수량이나 전체 오차율로 합산하지 않는다. 시안의 ‘안전 허용범위’는 제거한다.

`이력보기`는 해당 재료의 입고·폐기·실측·기존 조정 기록을 보여주고 각 기록을 수정·삭제할 수 있게 한다. 판매 소모량은 계산 근거로 구분해 보이며 독립된 재고 거래로 다시 저장하지 않는다. 조회·검색은 저장 자료·파일을 바꾸지 않는다.

### 입력창과 유형별 항목 — 추천 적용

공통 항목은 일자·기존 재료·유형이 필수이고 사유/메모는 선택이다. 시안의 `재고 변동 기록`, 닫기, 취소, `변동 기록 저장`에 연결한다.

| 유형 | 입력 | 처리·결과 |
| --- | --- | --- |
| 입고 | 구매 묶음 수 또는 기준단위 수량 중 하나, 구매 금액(미입력 가능) | C06으로 기준단위 수량 환산. 재고 증가. 금액이 있으면 입고 단위원가 보존. 구매금액만으로 가격 이력을 바꾸지 않음 |
| 폐기 | 버린 기준단위 수량을 양수로 입력 | 내부 증감량은 음수. 재고 감소. 구매금액·구매 묶음 입력은 숨김 |
| 마감 실측 | 마감 후 실제로 센 기준단위 수량. 0 가능 | C08로 같은 시점 장부량과 차이를 보여줌. 실제 수량을 새 기준점으로 보존. 차이만 또 더하지 않음 |

입고·폐기의 수량은 0보다 커야 한다. g·ml는 소수 입력 가능, 개는 정수다. 구매금액은 0 이상 원 정수이고 미입력이 원가 0을 뜻하지 않는다. 입력 단위를 kg·L로 자동 추정하지 않는다. 화면의 단위와 자료 기준단위를 일치시킨다.

수정·삭제 성공 시 관련 재료의 해당 날짜 이후 잔량을 재검토한다. 뒤에 있는 다른 실측 기준점의 **실제 수량 자체**는 바꾸지 않으며 그 시점 장부와의 차이는 바뀔 수 있다. 같은 재료·날짜의 마감 실측은 하나만 허용하고 추가하려 하면 기존 실측 수정 안내. 기존 기록 ID를 유지한다.

오류: 잘못된 날짜·미래 기록·초기재고 이전 기록·모르는 재료·단위 오류·음수 실측은 저장 차단. 재료 구매용량이 없는데 묶음 수를 입력하면 환산을 막고 기준단위 수량 입력 안내. 폐기가 장부량을 초과하거나 판매 변경으로 잔량이 음수가 되면 임의로 0에 맞추지 않고 ‘재고 확인 필요’ 표시 후 실제 거래 기록은 보존한다. 레시피·단위 누락으로 소모량을 모르면 해당 재료 잔량은 확인 필요이며 나머지 재료 결과는 독립적으로 표시한다. 금액 원가만 누락되고 레시피 사용량을 알 수 있다면 재고 소모량 계산은 유지한다.

## 9. 계산 기준 — 추천 적용

기존 순매출·개당원가·수수료는 과거 원본으로 유지한다. 아래 식은 신규·수정 기록과 조회 결과의 계산 기준이다. 기존 값과 식이 다르면 원본을 자동 덮지 않고 확인 필요로 구분한다.

| 번호 | 계산 | 방법과 예외 |
| --- | --- | --- |
| C01 순매출 | 판매수량 × 당시단가 − 할인총액 | 할인총액은 행 전체의 양수 공제액. 기존 순매출에는 할인을 또 빼지 않음 |
| C02 메뉴 개당원가 | 재료별 (구매묶음 가격 ÷ 묶음용량) × 레시피 개당사용량을 합산 | 판매일 이하 적용시작일 중 가장 최근 가격, 기록의 레시피 버전 사용. 식재료와 포장재는 따로 합산. 채널 전용 재료는 해당 채널만. 일반적으로 매장 포장비는 명시적 0 |
| C03 행 공헌이익 | 순매출 − 수량×당시 식재료 개당원가 − 수량×당시 포장 개당원가 − 실제 수수료 금액 | 원가·수수료 미입력은 계산 확정 불가. 실제 0은 유효 |
| C04 메뉴 기간 집계 | 해당 메뉴 행의 판매량·순매출·비용·공헌이익 각각 합산. 이익률 = 공헌이익 합계 ÷ 순매출 합계 ×100 | 메뉴별 또는 합계 비율을 단순 평균하지 않음. 분모 0이면 ‘계산 불가’. 평균 개당원가는 총 원가 ÷ 판매수량 |
| C05 매장 운영손익 | 전체 공헌이익 합계 − 귀속일이 기간에 속하는 비용기록 합계 | 월계획·재료 구매대금 별도 합산 없음. 폐기손실 금액 별도 계산 없음. 이익률은 운영손익 ÷ 순매출 ×100, 분모 0이면 계산 불가 |
| C06 입고 환산 | 묶음 수 × 해당 구매용량 = 기준단위 입고량. 입고 단위원가 = 구매총액 ÷ 입고량 | 동일 입력에서 묶음과 기준수량을 중복 가산하지 않음. 구매금액 미입력일 때 단위원가 미확인 |
| C07 판매 소모 | 판매수량 × 레시피 개당사용량 | 재료·단위별 합산. 포장 전용 사용량은 포장 판매만. 금액의 저장 원가와 수량의 레시피 사용량을 구분 |
| C08 장부·실측 | 초기재고 또는 가장 최근 실측 이후의 입고·폐기·실측 없는 증감조정을 반영하고 판매 소모를 차감. 마감 실측 차이 = 실제로 센 수량 − 당일 마감 직전 장부량 | 실측 기록의 증감량과 실측수량을 둘 다 더하지 않음. 기준일 이후 기록 제외. 같은 날짜는 입고·소모·폐기/조정 처리 후 마감 실측 적용 |
| C09 구성비·일별 합계 | 채널 매출 ÷ 전체 매출, 비용항목 금액 ÷ 전체 비용. 날짜별 값은 동일 계산을 날짜로 묶음 | 분모 0·정보 부족이면 계산 불가. 평균 운영비는 달력상 확인된 대상 날짜 기준임을 명시하고 영업일 평균과 혼용하지 않음 |

자료의 재료가격이 없거나 구매용량이 0, 레시피 버전이 없거나 단위가 다르면 C02·C07의 해당 결과를 확정하지 않는다. 미래 가격이나 최초가격을 근거 없이 대신 사용하지 않는다. 포장 재료 구분은 원자료의 재료ID·적용채널을 사용하며 이름에 ‘컵’이 있는지만으로 판단하지 않는다.

### 숫자 표시·정밀도

돈 입력은 원 정수, 계산 중 재료원가는 소수를 보존한다. 중간 계산값을 화면 반올림 값으로 재사용하지 않는다. 최종 금액은 원 미만 반올림, 비율은 소수 둘째 자리 반올림하며 백업은 원본 정밀도를 보존한다. 반올림은 정확히 절반일 때 0에서 멀어지는 방향이다. 합계는 반올림 전 값의 합이며 행 표시 합과 차이가 생기면 반올림 차이라고 표시한다. g·ml는 입력 정밀도를 보존하고 개는 정수로 표시한다.

### 계산 예시와 검사 기준

아래 숫자는 설명을 위한 가정이며 원자료 실적이 아니다.

- 포장 라떼 10잔, 단가 4,800원, 할인총액 3,000원, 당시 식재료 개당원가 600원, 포장 개당원가 160원, 수수료 675원: 순매출 45,000원, 식재료비 6,000원, 포장비 1,600원, 공헌이익 36,725원, 이익률 81.61%.
- 위 판매만 있고 기간 공통 비용이 20,000원이면 매장 운영손익 16,725원이다. 월비용계획 금액을 다시 빼지 않는다.
- 우유 초기 1,000ml, 입고 2,000ml, 판매 소모 1,000ml, 폐기 100ml: 실측 직전 장부 1,900ml. 마감에 실제 1,800ml를 세면 차이 -100ml이며 새 기준은 1,800ml다. 조정 -100ml를 또 빼서 1,700ml로 만들지 않는다.
- 이후 과거 판매 소모를 900ml로 고치면 실측 직전 장부 2,000ml, 차이 -200ml가 되지만 실제 수량 1,800ml는 유지한다.

## 10. F09~F11 저장·백업·복원

### F09 저장

각 기록 저장·수정·삭제 성공 시 운영 자료에 반영한다. 같은 사용 환경에서 새로고침·다시 열기 후 기록과 당시 기준을 유지해야 한다. 저장 상태는 실제 성공 시각과 성공/실패를 보여주며 ‘동기화 완료’라고 표현하지 않는다. 일반 저장은 사용자의 다운로드 폴더에 파일을 만드는 동작이 아니다.

저장 공간 부족·권한·데이터 열기 실패 시 기존 자료를 자동 초기화하지 않는다. 기록을 읽을 수 있으면 조회·백업을 유지하고 쓰기 실패를 알린다. 최신 저장이 실패하면 미저장임을 명시한다. 기기·브라우저가 바뀌면 같은 자료가 자동 공유된다고 약속하지 않는다.

### F10 전체 백업

공통 `백업/복원`은 운영비용 및 데이터 관리의 해당 영역을 연다. `전체 데이터 백업 파일 다운로드 (.JSON)`은 현재 성공적으로 저장된 자료 전체를 파일로 만든다.

포함: 판매·비용·재고·실측·초기재고, 메뉴·재료·공급사·레시피·가격이력, 달력·월비용계획, 자료정보·적용한 운영 기준, 백업 형식 버전·생성시각·표별 건수. 계산 결과 화면만 저장하지 않는다.

파일명은 `prep_backup_YYYYMMDD_HHmmss.json`(한국 시각), 다운로드 결과는 생성 시각·건수와 함께 안내한다. 브라우저가 다운로드를 시작한 것과 실제 디스크 보관 완료를 구분한다. 다운로드 취소·차단·생성 실패 시 원본 변화 없음. 입력창의 미저장 내용은 백업에 포함하지 않으며 먼저 저장 여부를 안내한다. 1차 백업은 암호화 기능을 제공하지 않으므로 민감한 운영 자료가 담긴 파일임을 안내한다.

### F11 전체 복원

1. 파일 선택 또는 끌어놓기로 이 프로그램의 JSON 백업을 고른다.
2. 형식 버전·필수 자료·날짜·숫자·ID 중복·참조 관계·수량 단위·표별 건수를 검사한다. 원자료 JSON과 앱 백업은 용도가 다르므로 이름 확장자만 보고 복원하지 않는다.
3. 백업 시각·매장·기간·현재/복원 후 건수와 ‘현재 자료 전체 교체’를 보여준다. 합치기나 선택 복원은 없다.
4. 사용자가 교체를 확인하면 전체를 복원한다. 취소하면 기존 자료 그대로다. 교체 전 현재 자료 백업을 권한다.
5. 성공 후 목록·수익성·손익·재고를 복원 원본으로 다시 계산하고 저장 상태를 갱신한다. 입력창의 미저장 변경은 복원과 충돌하지 않게 버릴지 먼저 확인한다.

빈 배열은 구조가 유효하면 빈 운영 기록일 수 있으므로 명시적으로 확인 후 복원 가능하다. 필수 기준정보 자체 누락, 잘린 JSON, 알 수 없는 버전, 손상·ID 충돌·단위 오류는 교체 전에 중단한다. 복원 중 저장 실패는 전체 취소하며 기존 자료를 남긴다. 화면은 복원 성공을 가장하지 않는다. 값이 불완전한 과거 기록을 허용하는 기준은 초기 반영과 동일하며 확인 필요 상태까지 복원한다. 복원 결과로 새로운 다운로드 파일은 만들지 않는다.

## 12. 2차 확장 기능의 흐름과 계산 제안

아래는 PRD의 2차 요구를 빠뜨리지 않기 위한 정의다. 1차 버튼이나 처리에 포함하지 않는다. 실제 구현할 때 형식·정책을 구체화하며 현재 시안의 추가 기능을 승인한 것으로 해석하지 않는다.

| 초기 반영 후 재열기 | 같은 자료를 두 번 넣지 않음. 필수 표·건수·ID 연결 유지 |
| 판매 추가→조회 연결 | 저장 후 판매·메뉴·손익·재고가 동일 원본을 반영. 입력 중 취소는 원본 변화 없음 |
| 판매 수정·채널 변경·삭제 | 이전 집계/소모가 남지 않으며 포장 사용량은 해당 채널만 반영 |
| 비용 추가·수정·삭제 | 해당 기간 비용·손익 변경. 월계획과 중복 합산 없음 |
| 재고 입고·폐기·실측·수정·삭제 | C06~C08과 예시 충족. 이후 확정 실측수량은 과거 판매 수정에도 보존 |
| 누락·0·빈 기간·분모 0 | 확인 필요·기록 없음·유효한 0·계산 불가를 구분 |
| 부분 월·미마감·휴무일 | 미래 날짜를 매출 0으로 채우지 않음. 잠정 실적 표시. 휴무일 귀속 비용 유지 |
| 저장 실패·반복 클릭 | 기존 자료·입력 보존. 부분 저장·중복 행 없음 |
| 백업→수정→복원 | 백업 당시 원본·기준정보 복원, 다시 계산한 결과 일치 |
| 잘못된 백업·복원 취소 | 현재 자료가 바뀌지 않음 |
| 시안 범위 정리 | 필수 삭제 조작은 사용 가능. 제외 버튼과 예시 검증·암호화·POS 문구가 작동/보장처럼 남지 않음 |

계산값의 정답 검사는 반올림 전 값과 화면 표시값을 각각 확인한다. FRD 완료는 실제 구현·검사 완료를 의미하지 않는다.
